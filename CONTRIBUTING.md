# Contributing to TradingLab

Thanks for your interest in improving TradingLab.

## Before you start

- Check the existing issues and roadmap before opening a new one.
- Keep each change focused on a single topic.
- Avoid functional refactors unless they are explicitly requested.

## Development workflow

1. Create a branch for your change.
2. Make the smallest possible edit.
3. Run the relevant checks or tests.
4. Review the diff before committing.
5. Open a pull request with a clear summary.

## Commit messages

Use short, descriptive commit messages such as:

- `docs: improve README`
- `docs: add contributing guide`
- `chore: update repo templates`

## Pull requests

A good pull request should:

- explain what changed and why;
- stay within a single scope;
- include screenshots or logs only when they help;
- confirm that tests still pass.

## Code style

- Match the existing project style.
- Prefer small, readable changes.
- Keep documentation consistent with the codebase.

## Need help?

If something is unclear, open an issue and describe the problem or the proposal as specifically as possible.
